# RoRo v3 Tappa 0: base FastAPI + React Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sostituire Streamlit con un'app FastAPI + React in un solo servizio Docker per Hugging Face Spaces, con il gioco alla pari della v2, ponte 5 × 120 m e tabella su 3 livelli di domanda.

**Architecture:** L'engine `roro_yield/` non cambia. Il server è senza stato per il gioco: il browser tiene `seed` e `decisions`, e il server ricostruisce `GameSession` a ogni chiamata, così un riavvio non perde la partita. Solo i calcoli lunghi vivono nel server, come job in memoria letti con polling. FastAPI serve anche la build statica di React.

**Tech Stack:** Python 3.11, FastAPI, Uvicorn, Pydantic 2, HiGHS/PuLP; React 18, TypeScript, Vite, React Router, Vitest; Playwright; Docker.

**Spec:** `docs/superpowers/specs/2026-11-06-roro-v3-design.md`

## Global Constraints

- Branch `v3`. Nessun commit su `main` o `v2`.
- `git diff v2 -- roro_yield` deve restare vuoto per tutta la tappa.
- `ScenarioParams()` non cambia. Il ponte standard vive in `server/config.py`: `GAME_PARAMS = ScenarioParams(n_lanes=5, lane_length_m=120.0)`.
- Testo dell'app, README e commenti in inglese.
- Porta del container: 7860. Python 3.11.
- `ADVISOR_K = int(os.environ.get("RORO_ADVISOR_K", 20))`.
- Solver: solo HiGHS. Nessun servizio a pagamento.
- Al massimo 2 job di calcolo contemporanei; i job devono poter essere annullati.
- Dati sintetici sempre dichiarati: testo `Synthetic data, not DFDS data` nel footer.
- La tabella domanda usa `n_requests` = 35, 50, 60 per low, normal, high su 5 × 120 m, 30 seed (1..30), K = 20.
- Target su HF, demo 600 m e 60 prenotazioni: primo piano ≤ 30 s, verdetto ≤ 5 s.
- Interfaccia con la skill UI UX Pro Max se disponibile nella sessione; altrimenti scelte sobrie, senza libreria di componenti.
- Nessuna spesa e nessun deploy senza ok del proprietario.

## Review Focus

- Decisioni non valide o superate (id sbagliato, slot impossibile, partita già finita): risposta 422 con motivo leggibile, mai 500. Test in Task 2.
- Riavvio del server con partita aperta o job in corso: la partita continua, e un job sconosciuto dà 404 con messaggio e pulsante per rilanciare. Test in Task 3 e Task 8.
- Più visitatori insieme su 2 vCPU: oltre 8 job in coda il server risponde 429 e la pagina dice di riprovare. Test in Task 3.
- Valori estremi nel Lab (200 richieste, 16 corsie): il calcolo mostra avanzamento e si può annullare; valori fuori limite danno 422. Test in Task 5.
- Pagina ricaricata durante la partita: la partita riprende dal browser; se lo storage non è disponibile, la pagina funziona lo stesso. Test in Task 8.
